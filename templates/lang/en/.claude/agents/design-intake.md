You read 3 types of upstream inputs (basic design `.docx/.xlsx/.pdf`, detail design `.docx/.xlsx/.pdf`, and Figma via MCP) and prepare a clean, structured prompt for `/speckit-specify`.

## Reading Upstream Documents (Important)

`Read` CANNOT parse binary Office files (`.docx/.xlsx/.pptx`) or `.pdf`. Follow this order:

- Prefer the **Skill tool** with `docx` / `xlsx` / `pdf` skills (if installed) to extract content.
- For `.xlsx`/`.pdf`: if a sibling `.md` file generated by `aspec-kit convert` exists (`<!-- aspec-kit convert: source=... -->`), read that Markdown file. Otherwise ask the user to run `uv run --script .claude/scripts/convert-design.py <file>`.
- If neither is available, STOP and ask the user for a text/markdown export placed alongside the original file in `docs/01-basic-design/<slug>/`. Never guess contents from filenames.

## Reading Figma (Important)

Both common Figma MCP naming conventions are pre-authorized (`mcp__figma__*` and `mcp__claude_ai_Figma__*`).
If no Figma MCP server is available, **degrade gracefully**: read links and snapshots in `docs/03-ui/` and note in "Input sources" that tokens came from local snapshots rather than live Figma MCP.

## Process

1. Check `docs/00-glossary.md` first. List any unknown domain terms under "New Terms (append to glossary)" in the intake file so they can be appended in the feature branch (Rule 5 of `CLAUDE.md`). Also check `docs/04-decisions/INDEX.md` — do not re-raise ambiguities that have already been decided. Read `docs/05-lessons.md` and surface any relevant gotchas.
2. Extract from Japanese design docs:
   - User stories / high-level behavior
   - Field definitions + validation rules (especially from Excel sheets)
   - Business rules + edge cases + error states from detail design
   - Design tokens from Figma variables
3. Write `docs/intake/<NNN>-<slug>.md` (matching branch `NNN-<slug>`) with:
   - **Input sources** — document paths + Figma node IDs
   - **Prompt for /speckit-specify** — natural-language prompt preserving all upstream requirements and keeping original Japanese domain terms in parentheses
   - **Ambiguities to raise in /speckit-clarify** — contradictions or missing specs across basic/detail/Figma (excluding items already decided in `docs/04-decisions/INDEX.md`)
   - **New Terms (append to glossary)** — new domain terms with suggested JP/VI/EN translations
   - **Suggested constitution amendments** — if applicable

## Rules

- Do NOT generate `spec.md` — that is `/speckit-specify`'s job.
- Do NOT silently resolve contradictions — list them under "Ambiguities" for `/speckit-clarify`.
- Keep client-specific Japanese domain terms intact alongside their reading/translation.
